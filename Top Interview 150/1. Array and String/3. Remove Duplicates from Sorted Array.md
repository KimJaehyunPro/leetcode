## My Solution

**Performance:** 0 ms | **Beats:** 100.00%

```python
class Solution:
    def removeDuplicates(self, nums: List[int]) -> int:
        nums_length = len(nums)

        if (nums_length == 1):
            return 1

        replace_index = 1

        for i in range(1, nums_length):
            previous_num = nums[i-1]
            current_num = nums[i]

            if (previous_num != current_num):
                nums[replace_index] = current_num
                replace_index += 1

        return replace_index

```

### ✅ Method 2: Two-pointers

**Initial Intuition:**
Use a slow pointer to "lock" the "wanted" element, and a fast pointer to look for new unique elements. The elements between `slow` and `fast` are duplicates we can overwrite.

```python
def removeDuplicates(self, nums: List[int]) -> int:
    slow, fast = 0, 1
    while fast < len(nums):
        if nums[slow] == nums[fast]:
            fast += 1
        else:
            nums[slow+1] = nums[fast]
            fast += 1
            slow += 1
    return slow + 1

```

## What is the difference between `nums[:]` and `nums`, and how does the `[:]` syntax function in Python?

In Python, the difference between `nums` and `nums[:]` centers on **object reference** versus **slice assignment**. While they may look similar, they behave very differently when you are modifying data, especially in the context of "in-place" operations required by platforms like LeetCode.

### 1. `nums` (The Variable Reference)

When you use `nums`, you are referring to the **label** that points to a specific list object in memory.

* **Assignment (`nums = [1, 2, 3]`):** This creates a brand-new list object in memory and points the name `nums` to it.
* **The Problem:** If a function was given a specific list to modify, reassigning `nums` simply breaks the link to the original list and points it to a new one. The original list remains unchanged.

### 2. `nums[:]` (The Slice Operator)

The `[:]` syntax represents a **slice** of the entire list.

* **On the Right Side (`a = nums[:]`):** This creates a **shallow copy** of the list. It’s a new object with the same contents.
* **On the Left Side (`nums[:] = [1, 2, 3]`):** This is called **slice assignment**. Instead of creating a new list, it replaces the *contents* of the existing list object with new data.

---

### Key Differences Table

| Feature | `nums = new_data` | `nums[:] = new_data` |
| --- | --- | --- |
| **Action** | Rebinds the variable name. | Modifies the original object in-place. |
| **Object ID** | Changes (New memory address). | Stays the same (Same memory address). |
| **Impact** | Original list outside the function is untouched. | Original list outside the function is updated. |
| **Memory** | Efficient (just a pointer swap). | Slightly slower (replaces elements one by one). |

### Factual Evidence & Technical Details

* **The `id()` Function:** In Python, you can verify this using the `id()` function, which returns the memory address of an object.
```python
original = [1, 2, 3]
print(id(original))

original[:] = [4, 5, 6]
print(id(original))  # The ID remains exactly the same.

original = [7, 8, 9]
print(id(original))  # The ID changes!

```


* **PEP 227 and List Internals:** Python lists are implemented as contiguous arrays of pointers to other objects. Slice assignment is a highly optimized C-level operation that handles resizing the internal array if the new data is a different length than the old data.
* **Mutable vs. Immutable:** This distinction only matters for **mutable** objects like lists or dictionaries. For immutable objects like tuples, `[:]` still creates a copy, but you cannot perform slice assignment because the object cannot be changed.

### Interesting Facts for Casual Conversation

* **The "Secret" Copy:** Before Python 3.3, `nums[:]` was the most common way to copy a list. Now, `nums.copy()` is preferred for readability, but `nums[:]` is still 10–15% faster in some versions of CPython because it’s a single opcode (`BINARY_SLICE`).
* **Memory Efficiency:** If you use `nums[:] = sorted(set(nums))`, Python actually creates a temporary list in the background first, then copies it into the original. So, while it is "in-place" for the variable name, it still briefly uses  extra memory during the calculation!
